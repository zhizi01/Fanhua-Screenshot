# 繁花有图架构说明

## 桌面交互

程序默认只保留系统托盘和全局快捷键，不自动显示主窗口。托盘打开的是紧凑设置窗口；图片预览和编辑使用独立窗口，可以同时保留多张截图。

内部路由沿用 `dashboard`、`capture`、`preview` 三个值。其中 `dashboard` 对应设置窗口，不是页面导航式工作台。

## 进程职责

| 部分 | 文件 | 职责 |
| --- | --- | --- |
| Electron 主进程 | `electron/main.cjs` | 单实例、托盘、全局快捷键、截图会话、窗口生命周期、文件对话框和剪贴板。 |
| 预加载桥 | `electron/preload.cjs` | 通过 `contextBridge` 暴露明确的 `window.fanhua` 方法。 |
| 共享类型 | `src/shared.ts` | 截图上下文、窗口矩形、图片信息和桌面 API 契约。 |
| 设置视图 | `src/views/DashboardView.vue` | 截图入口、打开图片、启动设置、快捷键状态。 |
| 截图遮罩 | `src/views/CaptureView.vue` | 窗口命中、悬停高亮、框选、确认和取消。 |
| 预览编辑 | `src/views/PreviewView.vue` | 图片显示、标注交互、属性、图层和导出。 |
| Windows 服务 | `electron/native-helper.cjs`、`electron/native/windows.ps1` | 窗口枚举与已安装字体读取。 |

窗口关闭时删除关联截图数据。设置窗口的关闭操作改为隐藏；最后一个窗口关闭后，托盘和快捷键仍保留。只有显式退出程序才释放全局快捷键、停止原生服务并退出。

## 截图会话

一次最多有一个活动截图会话。处理顺序如下：

1. 记录本程序可见窗口和焦点，隐藏这些窗口，等待桌面合成更新。
2. 并行读取各显示器截图和 Windows 顶层窗口边界。
3. 每个显示器创建一个无边框、置顶的截图遮罩，保存该屏原始图像。
4. 渲染进程读取上下文，解码背景图，并在 DOM 更新后调用 `captureReady()`。
5. 主进程等待所有遮罩就绪，再统一显示，聚焦鼠标所在显示器。
6. 渲染进程只提交选区矩形。主进程校验和裁剪保存的原图，结束会话、恢复先前窗口并打开预览。

准备阶段有超时保护。取消、显示器增删或布局变化、截图渲染进程退出、窗口失去响应，都会清理该会话并恢复原窗口。`capture-lifecycle.cjs` 会检查事件所属会话，防止旧窗口的迟到事件取消新截图。

截图遮罩显示的是冻结画面。窗口识别使用同次准备阶段的边界，不会在截图过程中持续追踪后台窗口变动。

## 坐标约定

系统、窗口和图像使用不同坐标系：

- `screen.getAllDisplays()` 返回显示器的 DIP 边界，允许副屏位于负坐标。
- Windows 原生服务返回物理像素窗口边界，按前景到背景保留枚举顺序。
- 截图遮罩的矩形使用当前显示器左上角为原点的本地 DIP。
- 编辑图层使用原图像素坐标，不随预览缩放变化。

对于跨越不同 DPI 显示器的窗口，先在物理坐标中与每个显示器求交集，再换算为该屏的本地 DIP。不能先把整个窗口按单一缩放比例转换。

设显示器本地逻辑尺寸为 `W × H`，截图真实尺寸为 `Pw × Ph`，选区为 `(x, y, w, h)`。裁剪先夹紧屏幕边界，再计算：

```text
left   = floor(x * Pw / W)
top    = floor(y * Ph / H)
right  = ceil((x + w) * Pw / W)
bottom = ceil((y + h) * Ph / H)

pixelWidth  = right - left
pixelHeight = bottom - top
```

端点取整确保覆盖整个选区。尺寸提示与浏览器演示裁剪遵循同一规则，避免高 DPI 下提示值与导出尺寸相差一像素。

编辑画布把鼠标在 CSS 画布中的相对位置乘以自然图像尺寸，得到原图坐标。缩放只影响显示和选择框线宽，导出始终按原图尺寸绘制。

## Windows 原生服务

主进程启动隐藏的常驻 PowerShell 子进程，第一次运行时编译内嵌 C#，后续通过按行 JSON 请求复用进程。

- 使用 `EnumWindows` 获取顶层窗口顺序。
- 过滤本程序、不可见、最小化、被系统隐藏的窗口及桌面壳窗口。
- 使用 DWM 可见边框，失败时回退窗口矩形。
- 保留真实无标题窗口，以窗口类名或“未命名窗口”显示。
- 过滤可穿透的被动工具遮罩，避免遮挡真实窗口命中。
- 字体列表来自 `InstalledFontCollection`。

PowerShell 脚本源码保持 ASCII，中文常量使用 C# Unicode 转义，避免 Windows PowerShell 5.1 对无 BOM 脚本的默认编码差异。进程标准输入、标准输出和 JSON 协议统一使用 UTF-8。

请求具有独立编号和超时。管道异常、EPIPE 或子进程退出会拒绝对应请求；下一次请求允许重新启动服务。打包时 `electron/native/**` 解包到 `app.asar.unpacked`，让系统 PowerShell 能读取真实文件。

## 非破坏编辑

`src/editor/model.ts` 定义三种图层：

- `TextLayer`：位置、文字、字体、字号、颜色。
- `MarkerLayer`：位置、序号数值、序号方式、说明和文字样式。
- `MosaicLayer`：位置、矩形尺寸、像素块强度。

`src/editor/render.ts` 每次先绘制原图，再绘制马赛克，最后绘制文字和序号。每个马赛克从原始图像采样，因此修改强度、移动或删除都不会累积破坏原图。

命中测试和图层列表与实际绘制顺序保持一致。同类图层中，后创建的图层位于上方；文字和序号始终显示在马赛克上方。

`EditHistory` 保存不可变图层快照，最多保留 100 个状态。拖动过程中只更新活动图层，完成拖动后提交历史；撤销后产生新编辑会丢弃旧的重做分支。

导出创建独立画布并调用同一个场景渲染函数，不绘制选择框、工具提示或其他编辑界面。PNG 只包含最终像素，不包含图层项目数据。

## IPC 和文件边界

渲染进程启用 `contextIsolation`、`sandbox` 和 `webSecurity`，禁用 Node.js 集成。预加载桥不暴露通用 IPC 或文件系统接口。

主进程按窗口身份和视图类型注册白名单操作，并只接受主框架发起的调用。选区须为有限数值并落在屏幕范围内；导出只接受 PNG data URL，检查文件头、图像尺寸和数据长度后重新编码。

Vue 响应式对象不能直接传入 Electron 的隔离桥。截图确认前显式复制 `x/y/width/height` 为普通对象，避免自动识别窗口产生的 Proxy 无法序列化。原生端到端测试覆盖单击窗口这条路径。

打开和保存路径来自系统文件对话框。复制操作由主进程写入剪贴板。窗口导航、新窗口创建和 WebView 挂接被拒绝。程序没有图片上传或远程图像处理路径。

## 开发与验证

Vite 负责渲染代码；`scripts/dev.mjs` 启动本机开发服务器与 Electron，并在任一进程退出时清理另一个进程。发布构建由 `electron-builder` 生成 Windows 程序目录与 NSIS 安装包。

- `tests/unit/`：坐标、窗口边界、PNG 校验、序号、编辑历史、马赛克采样和异常恢复。
- `tests/e2e/browser.spec.ts`：使用演示图片验证截图选择、属性编辑、无损删除和导出。
- `tests/e2e/electron.spec.ts`：启动真实 Electron 和独立测试窗口，验证原生窗口识别、图像尺寸、固定、保存、取消与后台常驻。

浏览器演示位于 `src/demo.ts`，不参与真实 Electron 屏幕捕获。测试产物、构建产物和依赖目录通过 `.gitignore` 排除；源码与文档统一 UTF-8，提交说明使用中文。
