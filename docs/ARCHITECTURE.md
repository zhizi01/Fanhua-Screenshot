# 繁花有图架构说明

## 桌面交互

1.5.0 继续采用桌面工具流程：程序默认只保留系统托盘和全局快捷键，不自动显示主窗口。托盘打开的是紧凑设置窗口；截图后直接进入独立预览，需要标注时展开工具栏和属性栏，可以同时保留多张截图。OCR 与中英译文使用图片右侧的独立段落栏，译文同步覆盖原图识别区域；保存格式和水印使用就地弹窗，复制和共享使用紧凑下拉菜单。图片支持 Windows 资源管理器入口和画布内部的右键菜单。

内部路由沿用 `dashboard`、`capture`、`preview` 三个值。其中 `dashboard` 对应设置窗口，不是页面导航式工作台。

## 图片右键入口

NSIS `customInstall` 在 `Software\Classes\SystemFileAssociations\.<扩展名>\shell\FanhuaScreenshot.Edit` 注册 PNG、JPG、JPEG、WebP、BMP 五种扩展，命令为带引号的程序路径与 `--edit-image "%1"`。注册表根使用 SHCTX，跟随安装器的当前用户（HKCU）／所有用户（HKLM）范围，避免管理员提升后写入错误用户账户。不写默认打开关联，`MultiSelectModel=Single` 限制单文件入口；卸载只有在命令仍指向本安装目录时删除自己的键，并通知 Shell 刷新关联。Windows 11 传统菜单通常在“显示更多选项”中。

首启与 `second-instance` 均交给 `handleLaunch`，仅显式 `--edit-image` 接受完整绝对路径。`requestSingleInstanceLock` 的 additionalData 携带原始参数，避免 Chromium 重排二次启动参数导致路径错位。读取限制为 96 MB、32768 单边和一亿像素，按实际文件头验证格式；PNG/JPEG 使用 Electron NativeImage，WebP 惰性加载 Sharp，BMP 支持 24/32 位 BI_RGB，校验像素偏移、步长和数据长度。普通“打开图片”和右键入口共用解码器。右键入口传递 `initialEditing` 并使用编辑窗口尺寸，不会先打开设置；读取与编辑不改写源文件。

画布内部右键在原图坐标命中标注，菜单可编辑、复制 PNG、保存、撤销、重做及删除选中标注。空白处清除旧选择，菜单约束在窗口内；方向键导航、Esc 关闭并恢复焦点，右键本身不会创建标注。

## 截图会话流程

程序启动后按显示器预加载透明、无边框、置顶的遮罩窗口；空闲时保持隐藏。`overlayPool` 按显示器 ID 复用这些窗口，避免每次快捷键都重新加载渲染页面。预加载失败时，下一次截图可重新创建。

一次最多有一个活动截图会话。处理顺序如下：

1. 保存焦点；只有从设置或预览窗口点击截图时，才隐藏这个来源窗口并等待桌面合成更新。全局快捷键和托盘菜单截图不隐藏现有窗口，保留用户当前看到的桌面。
2. 并行读取各显示器截图和 Windows 顶层窗口边界。
3. 为每个显示器获取或创建遮罩，把原始图像与本次会话关联，发送包含 `sessionId` 的上下文。
4. 渲染进程重置上次选区、解码本次背景图，并在 DOM 更新后调用 `captureReady(sessionId)`；旧会话的就绪通知不能使新会话提前显示。
5. 主进程等待所有遮罩就绪，再统一显示，聚焦鼠标所在显示器。
6. 渲染进程提交选区矩形和会话编号，取消请求也携带编号，防止旧请求影响复用窗口中的新会话。主进程校验并裁剪保存的原图，结束会话、恢复来源窗口并打开预览。遮罩隐藏并清空上下文，留在池中供下次使用。

准备阶段有 20 秒超时保护，准备期间也可通过 `Esc` 取消。取消、显示器增删或布局变化、截图渲染进程退出、窗口失去响应，都会清理该会话并恢复来源窗口。`capture-lifecycle.cjs` 会检查事件所属会话，防止旧窗口的迟到事件取消新截图。显示器布局变化还会销毁旧遮罩池并重新预热。

截图遮罩显示的是冻结画面。窗口识别使用同次准备阶段的边界，不会在截图过程中持续追踪后台窗口变动。

## 坐标约定

系统、窗口和图像使用不同坐标系：

- `screen.getAllDisplays()` 返回显示器的 DIP 边界，允许副屏位于负坐标。
- Windows 原生服务返回物理像素窗口边界，按前景到背景保留枚举顺序。
- 截图遮罩的矩形使用当前显示器左上角为原点的本地 DIP。
- 编辑图层使用原图像素坐标，不随预览缩放变化。

对于跨越不同 DPI 显示器的窗口，先在物理坐标中与每个显示器求交集，再换算为该屏的本地 DIP。不能先把整个窗口按单一缩放比例转换。

设显示器本地逻辑尺寸为 `W × H`，截图真实尺寸为 `Pw × Ph`，选区为 `(x, y, w, h)`。裁剪先夹紧屏幕边界，再计算：

```text
left   = floor(x * Pw / W)
top    = floor(y * Ph / H)
right  = ceil((x + w) * Pw / W)
bottom = ceil((y + h) * Ph / H)

pixelWidth  = right - left
pixelHeight = bottom - top
```

端点取整确保覆盖整个选区。尺寸提示与浏览器演示裁剪遵循同一规则，避免高 DPI 下提示值与导出尺寸相差一像素。

编辑画布把鼠标在 CSS 画布中的相对位置乘以自然图像尺寸，得到原图坐标。缩放只影响显示和选择框线宽，导出始终按原图尺寸绘制。

`Ctrl + 滚轮` 先记录鼠标下方的原图坐标，再修改显示比例，等待布局更新后调整滚动位置，使该坐标仍留在鼠标下方。滚轮的像素、行、页增量先统一换算，并使用请求序号忽略迟到的布局更新。手动缩放限制在 5%～800%；适应窗口可使用更小比例。普通滚轮保留滚动行为，保存和水印弹窗打开时暂停画布缩放和编辑快捷键。OCR 段落栏不阻塞图片操作，其内部按键不会触发画布编辑命令。

## Windows 原生服务

主进程启动隐藏的常驻 PowerShell 子进程，第一次运行时编译内嵌 C#，后续通过按行 JSON 请求复用进程。

- 使用 `EnumWindows` 获取顶层窗口顺序。
- 过滤不可见、最小化、被系统隐藏的窗口及桌面壳窗口；可见的本应用预览也参与窗口识别，隐藏的截图遮罩自然排除。
- 使用 DWM 可见边框，失败时回退窗口矩形。
- 保留真实无标题窗口，以窗口类名或“未命名窗口”显示。
- 过滤可穿透的被动工具遮罩，避免遮挡真实窗口命中。
- 字体枚举合并 WPF `SystemFontFamilies`、当前用户字体目录与 GDI `InstalledFontCollection`。WPF `FamilyNames` 提供中文及其他本地化名称，并补齐 GDI 不完整的字体族；大小写不敏感去重，不截断列表。
- 主进程缓存字体查询结果，显式刷新会清空缓存；失败后允许重试。界面提供搜索、实际字体名称预览、数量及错误提示，不以默认字体列表冒充系统枚举成功。

PowerShell 脚本源码保持 ASCII，中文常量使用 C# Unicode 转义，避免 Windows PowerShell 5.1 对无 BOM 脚本的默认编码差异。进程标准输入、标准输出和 JSON 协议统一使用 UTF-8。

请求具有独立编号和超时。管道异常、EPIPE 或子进程退出会拒绝对应请求；下一次请求允许重新启动服务。打包时 `electron/native/**` 解包到 `app.asar.unpacked`，让系统 PowerShell 能读取真实文件。

## 非破坏编辑

`src/editor/model.ts` 定义六种图层：

- `TextLayer`：位置、文字、字体、字号、颜色。
- `MarkerLayer`：位置、序号数值、序号方式、说明、说明文字样式及独立的序号头直径。序号文字随圆头适配，较长序号缩小至圆头内部，不改变说明字号。
- `ArrowLayer`：起点、终点、颜色、线宽和箭头头大小。选中时显示两端控制点；整体拖动保持方向，端点拖动改变长度和方向，命中判定沿箭杆与箭头进行。
- `RectangleLayer`／`EllipseLayer`（合称 `ShapeLayer`）：外框位置与尺寸、颜色、线宽和实线／虚线／点线类型。边框向外框内部绘制；矩形按边线、椭圆按实际弧线距离命中，空心内部不抢占其他标注。选中后提供八个控制点，支持越过锚点反向调整并夹紧图像边界；`Shift` 可约束为正方形或正圆。工具快捷键分别为 `R`、`O`。
- `MosaicLayer`：位置、矩形尺寸、像素块强度。

`src/editor/render.ts` 每次先绘制原图，再绘制马赛克，然后按创建顺序绘制文字、序号、箭头和形状边框，最后合成水印。每个马赛克从原始图像采样，因此修改强度、移动或删除都不会累积破坏原图。形状线宽和虚线间隔使用原图像素，预览与导出复用 `paintShape`；选择控制点的大小则根据显示比例补偿。

命中测试和图层列表与实际绘制顺序保持一致。普通标注中后创建的图层位于上方；文字、序号、箭头和形状边框始终显示在马赛克上方。水印作为整张图片的独立配置，通过水印弹窗调整，不占用普通标注图层。

`DocumentHistory` 保存 `{ layers, watermark }` 不可变快照，最多保留 100 个状态。拖动过程中只更新活动图层，完成拖动后提交历史；撤销后产生新编辑会丢弃旧的重做分支。水印修改参与同一撤销链；不可变的图片 data URL 字符串在快照间复用，不为每次文字或位置修改重新复制图片字节。

导出冻结当前图层与水印配置，等待实际使用的字体及图片水印完成加载，再创建原始尺寸的独立画布并调用同一个场景渲染函数。不绘制选择框、控制点、OCR 虚拟框或其他编辑界面，导出的各类文件均不包含图层项目数据。

## OCR 与翻译边界

“识别文字”展开 `OcrSidebar.vue` 段落栏并自动发起识别。输入固定为 `screenshot.dataUrl` 中打开时的原图 PNG，识别整张图而非只识别可见视口。OCR 不调用场景导出函数，因此本次新增的文字、序号、箭头、形状、水印与马赛克不会进入 OCR 输入；保存和图片复制仍使用合成导出。请求发起时保留原图引用，结果返回时同时校验请求号与图片 ID，位置按该原图尺寸裁剪。主进程同一时间只允许一个识别任务，应用退出时中止所有任务。

原图保持不变，所以标注和水印历史不使识别结果过期；被本次马赛克覆盖的原始文字仍可识别。打开此前已导出的图片时，其中合成的标注已经属于原图像素，无法由图层逻辑剥离。

OCR 返回 `lines` 和 `paragraphs`，每个段落具有 ID、文字、原图像素包围框和所属行。Tesseract 返回的原生段落优先保留；Windows 只提供行时，由 `ocr-paragraphs.cjs` 根据行高、行距、水平重叠、缩进和对齐归并。页面留白分割帮助保持分栏阅读顺序，不声称能准确还原所有复杂排版。段落包围框取所属行的联合矩形，越界或无效行先被裁剪或剔除；复制全文以空行分隔段落。

识别位置使用画布同级的 DOM 遮罩呈现：虚线边框、轻微填色和段落编号按当前显示比例跟随图片，不进入 Canvas 场景或文档历史。它们不拦截绘制指针；预览模式或选择工具下，由原图坐标命中段落，再定位右侧列表。编辑图层及控制点优先于 OCR 区域，避免识别框阻止正常标注。反向点击列表时高亮图片区域，需要时只滚动画布工作区；段落栏定位只调整自身滚动，不使用会连带移动页面的 `scrollIntoView`。

段落文字可单独修正，修正只影响识别结果与文字复制，不改动图像或图层。关闭侧栏隐藏识别框，但保留当前预览窗口内的结果、已选段落和修正；识别完成时即使侧栏已关闭，也缓存本次结果，重新打开不会重复识别。主动重新识别读取同一原图，替换旧段落及手动修正文字。窗口卸载递增请求号，防止迟到结果更新已关闭的视图。

`electron/ocr.cjs` 先查询 Windows `OcrEngine` 和内置模型可用性。选定语言在系统中可用时优先调用 Windows；中英文原生能力不可用或识别失败时，可回退到内置 Tesseract.js。其他识别语言依赖系统安装情况。`auto` 优先原生简体中文；若没有原生中文且内置模型可用，使用中英离线模型；两者均不可用时才选系统首个语言。离线自动识别使用 `eng+chi_sim`，明确选择英语时只使用 `eng`。

Windows 路径通过隐藏 PowerShell 进程调用 WinRT。超过系统 OCR 尺寸上限的图像按原始分辨率分块，并保留 96 像素重叠；返回的行坐标加回分块偏移。主进程消除重叠重复行、保留英文空格并清理汉字间多余空格，然后按阅读顺序输出。临时 PNG 放在专用临时目录，进程结束后清理。

离线路径使用独立 Node Worker 承载 Tesseract.js；WebAssembly 核心和 `eng`、`chi_sim` 模型随应用打包，不在运行时下载。原生识别和离线识别分别有超时保护，超时或应用退出时终止相关工作进程；关闭段落栏不终止后台任务，结果继续保存在本张图片的预览状态中。输入检查 PNG 文件头、字节数与尺寸；识别图片最多 96 MB、单边 32768 像素且总像素不超过一亿。

## 中英本地翻译

`src/services/translation.ts` 管理 OCR 段落的翻译状态。用户明确选择 `en-zh` 或 `zh-en`，可翻译全部或单段；逐段进度带请求编号、方向、段落 ID、原文和译文。界面仅接收当前图片、当前请求、同一方向且原文仍一致的结果。编辑原文使对应旧译文失效；重新 OCR、换方向、关闭识别栏或卸载视图会取消在途翻译。已完成译文可复制，保存图片不经过此状态。

`TranslationOverlay` 位于 OCR 区域 DOM 内，使用不透明度 97% 的白色遮罩与译文。隐藏测量元素按实际区域二分调整字号，屏幕字号最低 11px；放不下时截断，完整文字留在段落栏并作为画布悬停提示。ResizeObserver 与缩放变化触发重新排版，`pointer-events: none` 保留原有画布命中和编辑操作。关闭翻译恢复编号框，关闭 OCR 隐藏遮罩；段落结果的原文与方向不匹配时立即失效。该 DOM 不进入 Canvas 场景、文档历史及所有图片导出路径。

主进程只向预览窗口暴露翻译 IPC，并绑定发起窗口的 `webContents.id`。其他窗口不能取消该任务；窗口关闭或渲染进程退出时由 `cancelOwner` 兜底清理。主进程全局仅允许一个任务，避免多窗口同时加载模型造成内存和 CPU 争用。请求校验方向、编号、去重段落 ID、200 段上限、单段 12000 字符及总计 60000 字符。

`translation-worker.cjs` 通过 Electron `utilityProcess` 按需创建独立子进程，使用 Transformers.js 3.8.1 的 Node CJS 后端加载 OPUS-MT ONNX Q8，显式使用 CPU、2 个算子内线程和 1 个算子间线程。主进程和渲染进程不执行模型推理。一次仅保留一个方向的 pipeline，方向切换先释放旧模型；空闲 60 秒后终止子进程。取消、失败、超时或退出都会终止相关子进程，下一次等待旧进程退出后重新创建。原生推理与主程序进程隔离，取消不会在主进程中强杀 ONNX 工作线程。无进度等待限时 120 秒，整批任务最长 10 分钟。

英译中输入包含目标语言标记 `>>cmn_Hans<<`。逐行保留换行，长行优先按句子分割，再按实际 tokenizer 数量切成不超过 192 个输入 token 的片段，禁止 tokenizer 自动截断。生成最多 384 个新 token，检查 EOS 与长度限制，超限时提示拆分而不把截断结果标成完成。纯数字和符号行保留。

模型从固定本地资源目录读取，`allowRemoteModels = false`、`local_files_only = true`，不使用网络回退或用户缓存。两个方向的文件清单、revision 和 SHA-256 固定在 `resources/translation/manifest.json`。`models:prepare` 仅在开发准备阶段从官方 HTTPS 来源下载并校验；`models:check` 在打包前核对所有文件。安装包附带权重、配置、分词器、署名及许可，运行时无需下载。翻译子进程脚本和 ONNX／Sharp 原生依赖使用真实解包路径，Windows 包排除其他平台运行库及未使用的 Web 后端资源。

## 保存格式

`SaveExportDialog.vue` 提供 PNG、JPEG、WebP、BMP；JPEG、WebP 可选 10%～100% 质量。PNG 和 WebP 保留透明度，JPEG 和 BMP 在场景绘制完成后把透明区域合成到白底。

渲染进程使用 Canvas 编码 PNG、JPEG、WebP。BMP 通过 PNG 中间数据传到主进程后编码为 24 位、按行补齐的位图；浏览器演示使用 `src/editor/export.ts` 编码。主进程校验 MIME、文件头、尺寸及数据长度；PNG 重新编码，JPEG 保留已选质量的编码结果。由于 Electron 原生图片解码能力不覆盖 WebP，WebP 使用专门的容器与尺寸检查。

系统保存对话框按选定格式设置筛选器。若用户输入不匹配的扩展名，主进程拒绝并提示重新保存，不擅自改写已确认路径。取消对话框不标记为已保存。复制与共享和文件保存共用场景合成逻辑，包含标注和水印，不包含选择控件、OCR 虚拟框及译文。

普通复制与 `Ctrl+C` 使用 PNG。DeskFlow 模式由渲染进程在原始尺寸白底合成画布上调用 `toDataURL('image/jpeg', 0.6)`，只进行一次有损编码；主进程检查 JPEG 段、尺寸和实际解码结果。异步 `ClipboardItem` 同时提供普通图像、原始 `JFIF` 和原始 `image/jpeg` 注册格式，保留原始 JPEG 字节及兼容图片表示，不在主进程重新编码成 JPEG。普通 PNG 复制会替换旧的 JPEG 表示；错误输入在写入前拒绝，不清空当前剪贴板。DeskFlow Windows 的位图转换意味着 JPEG 字节数不等于其网络传输大小，详见 [DeskFlow 说明](DESKFLOW.md)。

## LocalSend 交接

`localsend:share` 仅接受预览窗口提交的合成 PNG，不接受渲染进程提供磁盘路径或程序路径。服务从记住的位置、正在运行的进程、注册表和常见安装目录查找 LocalSend，失败后使用系统文件选择器选择主程序；检查绝对路径、文件名与 PE 文件头。选择结果可保存到应用用户数据目录的 `localsend.json`，无效旧配置不会阻止重新选择。

图片写入系统临时目录下 `fanhua-localsend` 的唯一命名 PNG，随后以 `spawn(executable, [imagePath], { shell: false })` 调用 LocalSend。不拼接 shell 命令、不实现私有网络接口，也不替用户选择接收设备。已有实例由 LocalSend 自身接收路径并唤醒。成功反馈仅表示程序交接完成，不表示远端收到图片。

共享准备全局互斥，防止多个窗口同时弹出程序选择器。选择器取消，或程序选择结束时来源窗口已经关闭，不继续启动；启动失败清理当次文件。成功交接文件保留供 LocalSend 延后读取，关闭本工具不立即删除；初始化与再次分享时仅删除专用目录内符合本工具命名规则、非链接且超过 7 天的文件。其他文件不被清理。实际调用依据见 [LocalSend 说明](LOCALSEND.md)。

## 水印与持久化

`WatermarkConfig` 保存启用状态、文字或图片类型、字体/字号/颜色、图片尺寸与缩放、九宫格位置或平铺、透明度、角度、边距和间距。`WatermarkPanel.vue` 实时发出显式复制的普通对象，避免 Vue Proxy 进入隔离桥。选择图片先成功解码再更新，导出时再次确保图片与字体就绪；缺少图片的已启用水印会阻止导出并提示修正。

`src/watermark/layout.ts` 使用旋转后的包围盒定位边角水印，过大时等比例缩小以适应图片，保留边距并避免贴边裁断。全图平铺交错排列，自动限制到最多 1600 个实例，避免大图与过小间距使界面卡住。`render.ts` 维护最多 3 张已解码图片的缓存，合并并行加载请求，失败后允许重试；绘制保存并恢复 Canvas 状态、限制透明度并裁剪在原图范围内。

原生图片水印导入支持 PNG/JPEG，源文件最多 16 MB、1600 万像素，最长边超过 2048 时等比例缩小，统一转 PNG 并保留透明度。转换后最多 8 MB。浏览器演示使用图片解码和 Canvas 完成相同的缩放与 PNG 转换。

桌面存档位于 `app.getPath('userData')/watermarks.json`，保存版本、ID、名称、完整配置与更新时间。`createPresetStore` 把修改操作排入同一 Promise 队列，避免多个预览窗口同时保存造成覆盖；读取等待前面的修改完成。每次更新先写同目录的唯一临时文件，再重命名替换目标文件，并清理残留临时文件。

存档读写校验全部字段和图片数据，限制最多 30 个存档、单张 PNG 8 MB、整个 UTF-8 存档文件 64 MB；损坏、权限或磁盘错误会明确返回失败，不以空列表掩盖损坏文件。另存创建新 ID，更新要求原 ID 存在，删除仅影响指定存档。浏览器模式的存档使用 `localStorage`，受浏览器配额约束，不与桌面存档共享。

## IPC 和文件边界

渲染进程启用 `contextIsolation`、`sandbox` 和 `webSecurity`，禁用 Node.js 集成。预加载桥不暴露通用 IPC 或文件系统接口。

主进程按窗口身份和视图类型注册白名单操作，并只接受主框架发起的调用。选区须为有限数值并落在屏幕范围内；图像、格式、质量、字体刷新参数、识别语言、水印字段与存档 ID 都在主进程再次校验。OCR、导出与水印导入分别使用对应的大小和类型限制，预加载桥不接受任意磁盘路径。

Vue 响应式对象不能直接传入 Electron 的隔离桥。截图确认前显式复制 `x/y/width/height` 为普通对象，避免自动识别窗口产生的 Proxy 无法序列化。原生端到端测试覆盖单击窗口这条路径。

打开图片的路径来自系统文件对话框或显式 `--edit-image` 参数，保存路径来自系统保存对话框；水印存档只能访问应用固定的用户数据文件。图片和文字复制由主进程写入剪贴板。窗口导航、新窗口创建和 WebView 挂接被拒绝。OCR 和翻译仍在本机运行；用户主动共享时由 LocalSend 承接后续设备选择和传输。

## 开发与验证

Vite 负责渲染代码；`scripts/dev.mjs` 启动本机开发服务器与 Electron，并在任一进程退出时清理另一个进程。当前版本 1.5.0，仅发布 Windows x64 程序目录与 NSIS 安装包，尚未配置代码签名。`package.json` 限制 `os=win32`，开发、启动、构建与打包前检查 Windows x64；命令显式固定 Windows x64，`beforePack` 再校验实际目标以拒绝其他平台或架构。构建复用项目已安装的 `node_modules/electron/dist` 运行库。OCR 与翻译模型通过 `extraResources` 放入资源目录；PowerShell、OCR 工作线程、翻译子进程及其运行依赖通过 `asarUnpack` 提供为可读取文件。

- 工作区既有 `tests/` 删除保持不变，历史单元及端到端记录参见 `docs/VALIDATION.md`，本轮使用下列独立脚本。桌面测试使用隔离用户数据目录，避免与正在运行的旧版本共用单实例锁或水印存档。
- `scripts/verify-windows-target.cjs`：检查 Windows x64 构建约束与其他平台、架构的拒绝路径。
- `scripts/verify-windows-integration.cjs`：图片解码与输入限制、安装宏、首启及已有实例图片编辑；支持传入打包 EXE。
- `scripts/verify-context-menu.cjs`：真实 Electron 画布右键编辑、标注选择与删除、历史、菜单定位与焦点；支持传入打包 EXE。
- `scripts/verify-translation-service.cjs`、`verify-translation-inference.cjs`：翻译输入与生命周期回归，以及禁止网络调用后的真实模型推理、取消和异常恢复。
- `scripts/verify-translation.cjs`：真实 Electron OCR 到翻译全流程；传入 EXE 路径可复验打包程序，包含翻译中截图、终止任务子进程后恢复、窗口归属及导出隔离。
- `scripts/verify-image-clipboard.cjs`、`verify-localsend.cjs`、`verify-sharing-ui.cjs`：真实图片剪贴板字节／像素、LocalSend 交接与临时文件生命周期、分享菜单／压缩参数／窄窗布局与失败恢复。分享界面脚本支持传入打包 EXE 路径。

浏览器演示位于 `src/demo.ts`，不参与真实 Electron 屏幕捕获。测试产物、构建产物和依赖目录通过 `.gitignore` 排除；源码与文档统一 UTF-8，提交说明使用中文。

当前不支持一次拖动跨多块显示器连续框选，跨屏窗口只截取所在遮罩对应的可见部分；不提供 macOS、Linux 或 Windows ARM64 发行版。中英以外翻译、图层项目文件、自动保存和截图历史均未实现。架构中的能力描述不替代真实系统与安装包验证。
